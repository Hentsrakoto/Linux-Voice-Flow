# Adaptateur Groq — moteur Python

Tâche 1 de `plan-groq.md` implémentée. Le CLI accepte `--provider local|groq` (local par défaut). En Groq, le chemin absolu fourni par Rust identifie la session JSONL et ne demande aucun poids Whisper. Une préparation réussie valide la configuration et les dossiers ; elle n'appelle pas l'API et ne prouve donc pas encore la validité distante de la clé.

`engine/groq_config.py` lit `.env` à la racine du projet indépendamment du dossier courant. Seules `GROQ_API_KEY` et `GROQ_MODEL` sont utilisées ; variables d'environnement prioritaires. Valeurs simples ou entre guillemets, sans shell ni interpolation. Le modèle par défaut est `whisper-large-v3` ; seuls celui-ci et `whisper-large-v3-turbo` sont acceptés. Entrée bornée à 64 Kio, fichier régulier, lien final refusé. Le `repr` de configuration masque la clé. Une clé vide ou invalide produit `API_CONFIG_ERROR` sans exposer de valeur.

`engine/groq_transcriber.py` envoie un WAV multipart à l'endpoint HTTPS fixe de Groq, certificat vérifié, sans redirect ni nouvelle tentative automatique. Le nom de fichier envoyé est générique. Langue fr/en explicitement envoyée ; auto omet ce paramètre. Réponse `verbose_json`, limitée à 1 Mio, types et langue vérifiés ; seuls fr/en sont retournés au protocole. Les codes distinguent configuration, authentification, quota, indisponibilité et délai réseau. Ni corps d'erreur distant ni exception brute ne sont renvoyés.

La validation audio est extraite dans `engine/audio_input.py` et partagée avec le modèle local : dossier privé 0700, fichier régulier possédé 0600, aucune traversée ou lien symbolique, WAV mono PCM16/16 kHz, durée maximale 60 s, taille bornée et troncature vérifiée. Avant upload, le VAD Silero déjà distribué avec faster-whisper détecte les silences ; aucun poids Whisper n'est chargé. Les variables anti-télémétrie sont définies avant l'import natif. L'annulation est vérifiée avant VAD, avant réseau et après réponse ; le contrôleur Rust conserve l'arrêt forcé après son délai d'annulation et ignore les résultats tardifs. Un fichier déjà reçu par le service ne peut pas être rappelé.

Fichiers : nouveaux modules `errors.py`, `audio_input.py`, `groq_config.py`, `groq_transcriber.py` ; ajustements `transcriber.py`, `main.py`, `protocol.py`, `runtime.py` ; tests `test_groq.py` et extensions `test_cli.py`. Aucun SDK ni nouvelle dépendance ajouté.

Validation : nouveaux tests écrits avant l'implémentation, premier échec `ModuleNotFoundError` pour les nouveaux modules, puis succès. Suite Python complète : **79 réussis, 1 test de parole réelle sauté, 77 sous-tests réussis**. Après nettoyage des imports, suite ciblée Groq/CLI/transcriber : **63 réussis**. Tests couvrent dotenv, clé masquée, défaut/choix du modèle, multipart, langue auto/fr/en, HTTP 401/403/429/400/500/302, timeout, réponse invalide/trop grande, annulation avant et pendant requête, entrées privées, silence réel via VAD, CLI sans poids, CLI sans clé et pipeline JSONL→WAV→transport simulé→résultat. Aucun appel réel Groq ni microphone enregistré.

Le timeout urllib de 45 s borne les opérations réseau ; le superviseur Rust impose en complément son budget global existant de transcription (120 s) et d'annulation (3 s). Le test bloque les connexions Python et n'est pas présenté comme un pare-feu de bibliothèques natives. La recette avec une vraie clé et une phrase consentie reste à réaliser par l'utilisateur.

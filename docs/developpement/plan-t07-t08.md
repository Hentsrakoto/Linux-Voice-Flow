## Décisions et invariants

- Navigation à deux vues Dictée / Réglages. Réglages dans une vue dédiée, pas un formulaire sur le tableau principal. Le raccourci affiché suit le raccourci réellement enregistré. Boutons natifs accessibles, focus visible ; styles existants simplifiés. Palette #f5f6f2/#ffffff/#203932/#52665e/#176a57/#d5dfd8 ; sans système et mono utilitaire. Signature visuelle : les touches du raccourci comme commande centrale, pas de faux microphone animé ou de données simulées.
- Insertion activée par défaut (CDC), copie automatique désactivée par défaut. Capturer la fenêtre active et le focus X11 au début de la capture, vérifier leur existence et égalité immédiatement avant insertion et entre blocs. Ne jamais changer le focus pour forcer une insertion. Une annulation/génération périmée interdit toute nouvelle frappe. Aucun retry automatique après une insertion incertaine. Les contrôles (retour ligne/tabulation) ne doivent pas soumettre un chat ni déclencher de raccourci : texte imprimable lors de la frappe directe, sinon fallback explicite. La position du curseur dans une même fenêtre reste une limite documentée.
- Utiliser xdotool encapsulé pour la frappe UTF-8 et le focus, xclip pour le presse-papiers. Arguments fixes, chemins résolus et validés ; texte transmis par stdin, jamais shell/arguments/logs. Processus bornés, stderr jeté, enfants récoltés. Privilégier /usr/bin ; une extraction officielle dans `.tools/xdotool/usr/bin/xdotool` est admise pour ce poste de développement sans installer de paquet système. Diagnostic actionnable si absent. Le presse-papiers ne change que par Copier ou consentement de copie automatique ; effacer uniquement l’instance de presse-papiers possédée par notre processus xclip, sans restaurer/écraser une copie extérieure. Nettoyer les enfants à la fermeture.
- Réglages version1 atomiques dans `app_config_dir()/settings.json`, dossier0700/fichier0600, sans audio, texte, clé ni modèle Groq secret. Champs `schema_version:1`, `provider`, `model_path`, `microphone_id`, `language`, `shortcut`, `auto_insert_enabled:true`, `clipboard_auto_copy_consent:false`, `clipboard_fallback:true`, `max_recording_seconds:60` (plafond fixe de sécurité pour ce lot). Valider et appliquer sans opération active, préserver ancien réglage et raccourci si erreur ; ne pas écraser silencieusement un fichier corrompu. Recharger au lancement. Clé et modèle API restent dans `.env`.
- Préparer le fournisseur sauvegardé au démarrage quand configuration disponible, sans microphone automatique ; un chargement invalide reste récupérable dans Réglages. Avant toute sauvegarde Groq, informer l’utilisateur de l’envoi de l’audio. Aucun basculement automatique Local/Groq.
- Résultat éphémère120s, erreurs contrôlées, statut distinct `inserted` / `clipboard` / `preview` / `fallback` ; ne pas annoncer insertion réussie si seulement copié. Limite native : X11 ne garantit pas l’acceptation par tous les champs ; fallback disponible. Un message de chat ne doit jamais être envoyé par nos tests.

## Interfaces entre tâches

**Sortie desktop (agent A, fichiers insertion.rs/focus.rs)** : types publics `FocusTarget`, `OutputDiagnostics`, trait `DesktopOutput: Send` et implémentations `X11Output::new(project_root: PathBuf)` / `NoopOutput` pour tests existants. Méthodes synchrones bornées `capture_target() -> Result<FocusTarget, ErrorCode>`, `insert(target: &FocusTarget, text: &str, cancelled: &dyn Fn() -> bool) -> Result<(), ErrorCode>`, `copy(text: &str) -> Result<(), ErrorCode>`, `clear_clipboard() -> Result<(), ErrorCode>`, `diagnostics() -> OutputDiagnostics`. La capture renvoie une erreur si incertaine ; l’acteur conserve l’audio/transcription et propose le fallback plutôt qu’injecter aveuglément. Les noms exacts des champs du target sont internes au module.

**Intégration (agent B, reste Rust)** : conserver l’ancien `DictationService::spawn` pour tests (NoopOutput + insertion désactivée), ajouter constructeur de production avec sortie + options. Snapshot ajoute `delivery` (enum sérialisé snake_case : none/inserted/clipboard/preview/fallback), `clipboard_owned: bool`, `auto_insert_enabled: bool`, phase `inserting`. Options gardées dans l’acteur. Copier n’accepte aucun texte frontend : commande `copy_dictation_result` utilise le résultat présent côté Rust, erreur s’il est absent/expiré. `clear_dictation_clipboard` efface uniquement la sélection possédée. Les deux sont refusées pendant opération active. Annuler pendant insertion est observé par le callback sur les drapeaux atomiques de cancellation/epoch existants.

**T-08 IPC** : `get_settings() -> SettingsState {settings:Settings,error:string|null}` ; `save_settings({settings:Settings}) -> SettingsState` valide et sauvegarde sans charger de moteur implicitement côté UI ; le backend synchronise raccourci/options et préserve les anciens réglages si échec. UI prépare ensuite via `configure_dictation` existant (provider/model_path/microphone_id/language), ce qui rend l’activation du moteur explicite après Enregistrer. `get_diagnostics()` renvoie des booléens/états sûrs X11/audio/moteur/modèle/outils ; aucun secret. Les commandes de raccourci existantes restent disponibles pour compatibilité mais l’édition utilisateur passe par Réglages.

**UI (agent C)** : propriétaires App/navigation/hook partagé de snapshots dictation/hotkey/settings, DictationPanel réduit, SettingsPanel et diagnostic dans Réglages. `Settings` TS même JSON Rust. Restaurer la sélection après get_settings, enregistrer puis préparer, valeurs conservées après erreur. Désactiver les changements pendant loading/recording/transcribing/inserting/cancelling. Détection navigateur : aperçu statique honnête, pas de faux service prêt ; navigation et réglages visuels explorables sans vraie IPC. Aucun log/affichage d’exception brute.

# Installation réelle des modèles et validation hors ligne

Le 3 novembre 2026, Whisper Tiny multilingue a été installé dans `models/tiny/` depuis le dépôt public officiel `Systran/faster-whisper-tiny`, révision `d90ca5fe260221311c53c58e660288d3deb8d356`. Les quatre fichiers requis et le README représentent 78 205 610 octets ; les poids seuls représentent 75 538 270 octets. Le SHA-256 des poids correspond à celui des métadonnées officielles : `dcb76c6586fc06cbdac6dd21f14cfd129cc4cdd9dce19bf4ffa62e59cbe6e6d1`.

Le catalogue prépare aussi Whisper Base multilingue, révision `ebe41f70d5b6dfa9166e2c581c45c9c0cfc57b66`, mais ses poids ne sont pas installés. La connexion disponible étant lente, Tiny est livré utilisable immédiatement ; Base reste une installation explicite avec `.venv/bin/python scripts/install_models.py base`. Il apparaîtra dans le sélecteur seulement après une installation complète.

L'installateur utilise des révisions épinglées, refuse les liens symboliques, préserve les dossiers finaux inconnus, vérifie tailles et empreinte officielle des poids, puis écrit un reçu d'intégrité et publie le dossier de préparation. Les poids et reçus sont ignorés par Git. Aucun téléchargement n'est effectué pendant le démarrage de l'application ou la dictée. Le transfert Xet s'étant bloqué, l'installation de cette copie a utilisé HTTPS et des plages validées sur la même URL officielle ; les plages ont été assemblées puis vérifiées avec le SHA-256 officiel avant publication par l'installateur. Les fragments temporaires ont été supprimés.

Le premier contrôle avec le vrai moteur a révélé une incompatibilité jusque-là masquée par les tests simulés : faster-whisper 1.2.1 utilise encore `metadata_errors` dans PyAV, argument supprimé en version 19. Un nouveau test décode un vrai WAV sans modèle : il échoue avec PyAV 19.0.2. La dépendance est corrigée par `av>=11,<19` dans les contraintes et `av==18.1.0` dans le verrou. Aucun contournement n'est ajouté au moteur. Sources primaires : [versions PyAV](https://github.com/PyAV-Org/PyAV/releases), [incident amont faster-whisper](https://github.com/SYSTRAN/faster-whisper/issues/1589).

La télémétrie native ONNX Runtime est également désactivée avant import via `ORT_DISABLE_TELEMETRY=1`, conformément à la [documentation de confidentialité officielle](https://github.com/microsoft/onnxruntime/blob/main/docs/Privacy.md). Le contrôle bloque les connexions Python en complément ; il ne prétend pas constituer un pare-feu système.

Vérifications finales, sans adaptation temporaire des bibliothèques : PyAV 18.1.0 installé, `pip check` sans conflit, suite Python complète **43 tests réussis, 1 test de parole réelle sauté, 69 sous-tests réussis**. Cela inclut les cinq tests simulés de l'installateur et la régression de décodage WAV, devenue verte après correction. La vérification hors ligne du reçu Tiny passe. `scripts/check_models.py` charge le vrai `Transcriber` avec Tiny sur CPU/int8 en 0,942 s et traite un WAV privé de silence synthétique en renvoyant `NO_SPEECH` en 1,038 s au total ; les connexions Python sont bloquées et aucun avertissement de télémétrie n'est émis. Ces durées sont un constat ponctuel sur cette machine, sans engagement de performance.

La transcription de parole réelle et les performances sur vos phrases restent à vérifier manuellement avec votre microphone. Aucun enregistrement du microphone n'a été effectué pendant l'installation. Le test de parole optatif attend des WAV français/anglais fournis explicitement ; il n'est pas présenté comme validé.
